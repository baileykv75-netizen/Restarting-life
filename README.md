# Restarting Life

纯文字、规则驱动、不接入大模型 API 的修仙人生 Roguelike。

游戏设计与 V1 技术边界以 [`GAME_DESIGN_V1.md`](./GAME_DESIGN_V1.md) 为唯一功能基线。

## 当前开发阶段

**阶段 1：最小核心引擎**

阶段 0 已通过 GitHub Actions 自动验收。阶段 1 只实现可以被后续玩法复用的底层规则，不加入正式剧情、宗门、灵根、天赋或事件内容。

当前阶段实现：

- 单一 `GameState` 类型与确定性初始状态
- 基于 seed 的可重放伪随机数生成器，核心逻辑不使用 `Math.random()`
- 以整数月为唯一内部时间单位
- 凡人 / 炼气 / 筑基寿元表与自然死亡判定
- 最小修炼动作：一年 +55 修为，仅供引擎验证
- 已结束人生不可继续推进
- 对上述规则的独立单元测试

## 工程规则

```text
src/
├─ core/        # 规则与游戏引擎；状态变化从这里发起
├─ data/        # 静态游戏内容与数值表
│  └─ events/   # 阶段 3 才开始放正式事件数据
├─ types/       # 核心类型
├─ components/  # UI，不直接修改游戏规则状态
└─ store/       # 后续集中状态入口
```

阶段 1 保持纯函数优先，使随机、时间、寿元和修炼可以脱离 UI 独立复现与测试。

## 自动验收

每次提交到 `main` 后，GitHub Actions 自动执行：

```bash
npm install
npm run typecheck
npm test
npm run build
```

全部通过后，本阶段才允许封板。

## 本地运行（可选）

环境要求：Node.js >= 20.19。

```bash
npm install
npm run dev
```

## 阶段 1 验收条件

- 同一 seed 能生成相同随机序列；
- 时间只能以非负整数月推进；
- 凡人 80 年、炼气 120 年、筑基 220 年寿元规则可单测；
- 到达寿元边界后立即进入 `dead`；
- 死亡后不能继续推进；
- 炼气 / 筑基角色可以执行最小修炼动作；
- 凡人不能直接执行修炼动作；
- 一个测试角色可以稳定推进至寿终；
- TypeScript、测试和生产构建全部通过 CI。

阶段 1 通过前，不进入出生系统或正式事件系统。
